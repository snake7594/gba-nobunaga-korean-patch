# analysis/ — 조사·탐색용 스크립트

패치를 만드는 데는 필요 없습니다. **폰트와 텍스트 구조를 어떻게 찾아냈는지**를
그대로 남겨 둔 기록입니다. 다른 게임을 분석할 때 참고하거나, 이 저장소의 결론을
직접 재확인하고 싶을 때 쓰세요.

`tools/` 와 달리 이 스크립트들은 정리되어 있지 않고, 대부분 경로가 하드코딩되어
있거나 실행 시 인자를 요구합니다. 실행 전에 상단 경로를 확인하세요.

## 폰트를 찾아낸 경로 (동적 분석)

| 스크립트 | 한 일 |
|---|---|
| `gdbrsp.py` | mGBA GDB 스텁과 통신하는 최소 RSP 클라이언트 |
| `rsp_daemon.py` / `rsp_cmd.py` | GDB 세션을 유지하며 명령을 주고받는 데몬 (재접속 문제 회피) |
| `drv_dump.py` | VRAM 96KB / 팔레트 / OAM / IO 덤프 |
| `an_vram.py` | `DISPCNT`·`BGnCNT` 해석 후 BG 레이어를 PNG로 렌더 |
| `glyph_extract.py` | 렌더된 화면에서 글리프 비트맵을 픽셀 단위로 추출 |
| `glyph_search.py` | **핵심** — 추출한 비트맵을 7가지 인코딩 가설로 만들어 롬 전역 역검색 |

`glyph_search.py` 가 `packed12`(12비트 패킹, 글리프당 18바이트) 가설로 정확히 일치를
찾아내 폰트 주소 `0x305274` 를 확정했습니다.

### mGBA GDB 스텁 사용법

1. mGBA 실행 → 게임 로드 → 텍스트가 보이는 화면까지 진행
2. 메뉴 **도구 → GDB 서버 시작** (기본 포트 2345)
3. `python analysis/rsp_daemon.py` 로 세션 유지
4. 다른 창에서 `python analysis/drv_dump.py` 로 덤프

주의할 점:

- `m` 메모리 읽기는 **512바이트 이하**로 쪼개야 합니다 (초과 시 `E06`).
- 접속하면 코어가 정지합니다(`S02`). 작업 후 재개해야 합니다.
- 클라이언트가 `D`(detach) 없이 끊으면 스텁이 `CLOSE_WAIT` 로 남아 재접속을 거부합니다.
  그래서 세션 하나를 데몬으로 유지하는 방식을 씁니다.
- mGBA 0.10.5 기준으로 `--script`(Lua) CLI 로드는 동작하지 않고,
  `mgba-sdl -g` 는 포트를 열지 않습니다. **Qt 버전의 메뉴**를 쓰세요.
