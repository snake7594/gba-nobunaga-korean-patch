# 패치 적용 방법

한글 패치를 적용하는 방법은 두 가지입니다.

| 방법 | 대상 | 필요한 것 |
|---|---|---|
| **A. xdelta 패치 적용** (권장) | 그냥 한글로 플레이하고 싶은 분 | 원본 롬 + 패치 파일 |
| **B. 직접 빌드** | 번역을 고치거나 검증하고 싶은 분 | 원본 롬 + Python 3 |

어느 쪽이든 **원본 롬은 본인이 준비**해야 합니다. 이 저장소에는 게임 파일이 없습니다.

---

## 준비: 원본 롬 확인

| 항목 | 값 |
|---|---|
| 파일명 | `Nobunaga no Yabou (Japan).gba` |
| MD5 | `2d1ceffbc8c34e3101ab91ea49f43a44` |
| 크기 | 4,194,304 바이트 (정확히 4 MB) |
| 게임 코드 | `ANBJ` |

MD5 확인 방법:

```
Windows  : certutil -hashfile "Nobunaga no Yabou (Japan).gba" MD5
mac/Linux: md5sum "Nobunaga no Yabou (Japan).gba"
```

MD5가 다르면 다른 리비전이거나 이미 다른 패치가 적용된 롬입니다.
주소가 어긋나 패치가 깨지므로 그대로 진행하지 마세요.

---

# 방법 A — xdelta 패치 적용

## A-1. 파일 받기

[Releases](https://github.com/snake7594/gba-nobunaga-korean-patch/releases) 에서
`Nobunaga_Korean.xdelta` 를 받습니다. (저장소의 `patch/` 폴더에도 같은 파일이 있습니다.)

## A-2. GUI로 적용 (Windows, 가장 쉬움)

1. **xdeltaUI** 를 받습니다 — https://www.romhacking.net/utilities/598/
2. `xdeltaUI.exe` 실행 → **Apply Patch** 탭
3. 칸을 이렇게 채웁니다

   | 칸 | 넣을 것 |
   |---|---|
   | Patch | `Nobunaga_Korean.xdelta` |
   | Source File | `Nobunaga no Yabou (Japan).gba` (원본) |
   | Output File | `Nobunaga no Yabou (Korean).gba` (새로 만들 이름) |

4. **Apply** 클릭

> 원본 롬 파일명이나 경로에 한글·공백이 있어도 됩니다.
> 다만 잘 안 되면 영문 경로(예: `C:\rom\`)로 옮겨 보세요.

## A-3. 명령줄로 적용

xdelta3 를 받아 (https://github.com/jmacd/xdelta-gpl/releases) 실행합니다.

```
xdelta3 -d -s "Nobunaga no Yabou (Japan).gba" Nobunaga_Korean.xdelta "Nobunaga no Yabou (Korean).gba"
```

mac/Linux는 패키지로 설치할 수 있습니다.

```
# macOS
brew install xdelta
# Debian/Ubuntu
sudo apt install xdelta3
```

## A-4. 결과 확인

| 항목 | 값 |
|---|---|
| 패치본 MD5 | `7f4222b3140b0bc5d8084971375bd70c` |
| 크기 | 4,194,304 바이트 (**원본과 동일**) |

MD5가 일치하면 정상입니다. 크기가 원본과 같으므로 플래시카트·에뮬레이터 어디서든
추가 설정 없이 그대로 동작합니다.

## A-5. 실행

- **에뮬레이터**: mGBA, VisualBoyAdvance-M 등에서 패치된 `.gba` 를 열면 됩니다.
- **실기**: EverDrive GBA 등 플래시카트에 그대로 넣으면 됩니다.

세이브 파일(`.sav`)은 원본과 호환됩니다. 기존 세이브를 이어서 쓸 수 있습니다.

# 방법 B — 직접 빌드

번역을 수정하거나, 패치가 정말 이 저장소의 데이터에서 나오는지 검증하고 싶을 때 씁니다.

## B-1. 준비물

- **Python 3.8 이상**
- **Pillow** (이미지 생성용)

```
pip install -r requirements.txt
```

> `numpy`, `capstone` 은 `analysis/` 의 탐색용 스크립트에만 필요합니다.
> 패치를 만들기만 할 거라면 Pillow 하나면 됩니다.

## B-2. 원본 롬 놓기

둘 중 아무 방법이나 쓰면 됩니다.

**방법 1 — rom/ 폴더에 넣기** (권장)

```
gba-nobunaga-korean-patch/
└── rom/
    └── Nobunaga no Yabou (Japan).gba
```

**방법 2 — 환경변수로 지정**

```
Windows(cmd)  : set NOBU2_ROM=C:\path\to\Nobunaga no Yabou (Japan).gba
Windows(PS)   : $env:NOBU2_ROM = "C:\path\to\Nobunaga no Yabou (Japan).gba"
mac/Linux     : export NOBU2_ROM="/path/to/Nobunaga no Yabou (Japan).gba"
```

경로가 제대로 잡혔는지 확인:

```
python tools/paths.py
```

## B-3. 빌드

```
python build_patch.py
```

이것만 실행하면 패치 롬이 `build/Nobunaga no Yabou (Korean).gba` 로 만들어지고
검증까지 자동으로 돌아갑니다. 마지막에 이렇게 나오면 성공입니다.

```
주입 대조 : OK 7106 / 불일치 0
포인터 이상: 0
크기: 4194304 (원본과 동일: True ) 헤더 보존: True
>>> 검증 통과
...
  MD5     : 7f4222b3140b0bc5d8084971375bd70c
  기대값  : 7f4222b3140b0bc5d8084971375bd70c
  >>> 공식 배포본과 바이트 단위로 동일합니다
```

xdelta 패치 파일까지 만들려면:

```
python build_patch.py --patch
```

문자열 추출부터 전 과정을 다시 돌리려면:

```
python build_patch.py --full
```

## B-4. 번역 고치기

1. [`data/번역대조표.txt`](../data/번역대조표.txt) 에서 고칠 문장을 찾습니다.
2. [`data/tr_merged.json`](../data/tr_merged.json) 에서 해당 키를 찾아 값을 고칩니다.
   - 키는 **원문 일본어 문자열** 그대로입니다.
   - 단일 문자열은 `{"ko": "번역"}`, 여러 조각이 묶인 것은 `{"kos": ["...", "..."]}` 입니다.
3. `python build_patch.py` 를 다시 실행합니다.

필요한 한글 글리프는 자동으로 폰트에 새로 주입되므로 폰트를 따로 손댈 필요가 없습니다.

### 번역 수정 시 지켜야 할 것

| 규칙 | 이유 |
|---|---|
| `%s` `%d` `%2d` 같은 포맷 코드는 개수·순서 그대로 | 런타임에 이름·수치가 들어갑니다. 없애면 값이 안 나오고, 늘리면 엉뚱한 메모리를 읽습니다 |
| `{G00}`~`{G17}` 토큰 유지 | 게임 전용 외자(가이지)입니다 |
| `\n` 위치 유지 | 창 크기에 맞춰 줄이 나뉩니다 |
| 한 줄 전각 18자 이하 | 넘치면 화면 밖으로 나갑니다 |
| **일본어 한자·가나를 쓰지 말 것** | 그 글자 슬롯은 한글로 재활용되어 엉뚱한 글자가 나옵니다 |

마지막 규칙이 특히 중요합니다. 검사 도구가 잡아 줍니다.

```
python tools/validate2.py
```

수정 후 실제로 어떻게 보이는지 확인:

```
python tools/sample_sheet.py     # build/sample_korean.png
```

# 문제 해결

### `원본 롬을 찾을 수 없습니다`

`rom/` 폴더에 `.gba` 파일이 있는지, 또는 `NOBU2_ROM` 환경변수 경로가 맞는지 확인하세요.
`python tools/paths.py` 로 진단할 수 있습니다.

### `MD5가 기대값과 다릅니다` 경고

다른 리비전이거나 이미 패치된 롬입니다. 깨끗한 원본을 쓰세요.

### `ModuleNotFoundError: No module named 'PIL'`

```
pip install pillow
```

### 패치 적용은 됐는데 글자가 깨져 보임

원본 롬 MD5를 다시 확인하세요. 다른 리비전에 적용하면 주소가 어긋납니다.

### 빌드했는데 MD5가 공식 배포본과 다름

`data/` 의 파일을 수정했다면 당연히 달라집니다 (번역을 고쳤으니까요).
수정하지 않았는데 다르다면 이슈로 알려주세요.

### 세이브가 안 읽힘

패치본은 원본과 크기·세이브 형식이 같아 호환됩니다.
에뮬레이터가 `.sav` 파일명을 롬 파일명 기준으로 찾으므로,
세이브 파일명을 패치본 롬과 똑같이 맞춰 주세요.
