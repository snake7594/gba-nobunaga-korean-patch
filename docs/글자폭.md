# 글자 폭 문제와 해결

## 무엇이 문제였나

한자 독음은 1자 = 1음절이라 **이름·지명은 폭이 늘지 않습니다.**
`織田信長`(4칸) → `직전신장`(4칸). 실제로 DB 필드 4,491건 중 넓어진 것은 **0건**이었습니다.

문제는 **문장**입니다. 일본어는 한자의 압축률이 높아 같은 뜻을 짧게 씁니다.

| 원문 | 폭 | 번역 | 폭 |
|---|---|---|---|
| `娶る` | 2칸 | `아내로 맞았다` | 7칸 |
| `～に属す` | 4칸 | `～를 섬겼다` | 6칸 |

그 결과 인물 열전이 원문 72칸 → 번역 97칸까지 늘었습니다(최대 +25.5칸).

### 화면이 아니라 줄 수가 넘쳤다

게임에는 **자동 줄바꿈이 이미 있습니다**. 드로잉 루틴을 뜯어보면 이렇습니다.

```asm
08003eaa: adds r6, r7, #0     ; 전각 경로
08003eac: adds r6, #0xc       ; x 전진 12px (고정)
08003eae: mov  r1, r8
08003eb0: lsls r0, r1, #3     ; 폭 한계 = r8 * 8 px
08003eb2: cmp  r6, r0
08003eb4: bgt  0x8003eea      ; 넘으면 강제 줄바꿈 후 그 글자를 다시 처리
...
08003ee4: adds r6, #8         ; 반각 경로는 8px 전진
```

따라서 가로로 삐져나가지는 않고 **줄이 늘어납니다.**

원문 열전의 폭 분포를 보면 **864px = 18칸 × 4줄**이 312건으로 압도적입니다.
창이 18칸 × 4줄이고, 원문이 거기 꽉 차게 쓰여 있다는 뜻입니다.

측정 결과 장문 564건 중 **522건이 줄 수 증가**(1줄↑ 401건, 2줄↑ 120건)했습니다.
4줄 창에 5~6줄이 들어가 **아래가 잘렸습니다.**

## 어떻게 고쳤나

### 전진폭 12px → 7px (코드 6바이트)

글자 폭은 **세 곳에서 따로** 쓰입니다. 하나만 고치면 그리는 위치와 자리 계산이
어긋나 이름이 엉뚱한 x에서 시작하거나 창 밖으로 밀립니다. 여섯 군데를 전부 맞췄습니다.

| 주소 | 원래 | 지금 | 하는 일 |
|---|---|---|---|
| `0x003EAC` | `0C` | `07` | 그리기 루프 — 전각 전진 |
| `0x003EE4` | `08` | `07` | 그리기 루프 — 반각(1바이트) 전진 |
| `0x000AE6` | `0C` | `07` | `strwidth()` — 전각 (가운데·오른쪽 맞춤에 쓰임) |
| `0x000AEC` | `08` | `07` | `strwidth()` — 반각 |
| `0x000B20` | `0C` | `07` | 줄 수 계산 — 전각 |
| `0x000B2E` | `08` | `07` | 줄 수 계산 — 반각 |

7px 는 갈무리11 Condensed 한글의 잉크 폭과 정확히 같아, **획을 하나도 잃지 않으면서
넣을 수 있는 가장 좁은 값**입니다. 화면에 18칸 대신 **30칸 이상**이 들어갑니다.

### 갈무리11 Condensed 로 교체

| 폰트 | 한글 787자의 잉크 폭 |
|---|---|
| Galmuri11 | 10px 364자, 11px 423자 |
| **Galmuri11-Condensed** | **7px — 787자 전부** |

Condensed는 787음절이 예외 없이 7px에 들어갑니다. 7px 칸에 딱 맞습니다.

### 겹쳐도 획이 지워지지 않는 이유

그리기 루틴(`0x08003900`)은 12×12 글리프를 **불투명하게** 씁니다.
배경색 픽셀까지 쓰므로, 7px 전진이면 앞 글자의 오른쪽 5px를 뒷 글자가 덮습니다.

```
글자 N   : |◼◼◼◼◼◼◼·····|      잉크 0~6, 여백 7~11
글자 N+1 :        |◼◼◼◼◼◼◼·····|   x+7 부터
                   ↑ 덮이는 구간(글자 N의 7~11)은 전부 여백
```

잉크가 7px 이내이고 **왼쪽 정렬**이면 덮이는 부분은 항상 여백이라 손실이 없습니다.
그래서 `glyphs.py` 는 전진폭이 12 미만이면 자동으로 왼쪽 정렬로 전환합니다.

부수 효과로 x가 항상 8의 배수가 되어, 그리기 루틴의 **타일 정렬 고속 경로**만 타게 됩니다.

### 기호·외자도 같이 좁혔다

전진폭만 줄이면 원본 12px 글리프(기호·전각숫자·전각영문·외자)는 오른쪽이 잘립니다.
그래서 이들도 7px 안에 들어오도록 다시 그렸습니다.

| 대상 | 처리 | 건수 |
|---|---|---|
| 기호·전각숫자·전각영문 | Condensed 로 다시 렌더 (전각형이 없으면 NFKC 반각 대응) | 69 |
| `々` `∞` | Condensed 에 없어 원본을 가로 압축 | 2 |
| 가이지(게임 전용 외자) | 원본을 가로 압축 | 18 |

가로 압축은 원래 열을 목표 폭에 비례 배치하고 겹치는 열을 OR 해서 획을 보존합니다.
반각 폰트(ASCII 96자)는 원본 잉크가 전부 7px 이하라 그대로 두어도 잘리지 않습니다.

> 가이지를 한글 독음으로 바꾸는 방안도 검토했으나, 문맥이 다의적이라
> (예: `G06` 이 `恵瓊` 와 `撹乱` 양쪽에 나타남) 한자를 확정할 수 없어
> 오식별 위험을 피해 원본 압축을 택했습니다.

### 남은 21건은 번역을 다듬었다

전진폭 변경만으로 517건 → 21건이 되었고, 이 21건은 번역문을 원문 폭 이내로 줄여
**최종 0건**이 되었습니다. 대부분 짧은 대사이고 일부는 도움말 장문입니다.

```
쌀 시세가 높을수록 유리합니다. 병량 매매에 무장의 능력은 영향을 주지 않습니다. …
  ↓
쌀 시세가 높을수록 유리합니다. 병량 매매에 무장의 능력은 영향이 없습니다. …
```

## 되돌리거나 바꾸려면

전진폭은 환경변수로 바꿀 수 있습니다.

```
# 원본과 같은 12px 로 (갈무리11 일반, 가운데 정렬)
set NOBU2_ADVANCE=12
python build_patch.py

# 10px 절충안
set NOBU2_ADVANCE=10
python build_patch.py
```

`tools/glyphs.py` 가 전진폭에 맞춰 폰트(12px→일반 / 8px→Condensed)와
정렬(12px→가운데 / 그 미만→왼쪽)을 자동으로 고릅니다.

## 확인 도구

```
python tools/screen_preview.py     # 실제 롬 바이트로 화면 렌더 -> build/final_screens.png
python tools/font_preview.py       # 폰트 전체 미리보기
```

`screen_preview.py` 는 재배치된 문자열의 **포인터를 따라가** 현재 주소에서 읽고,
게임과 동일한 규칙(전진폭·자동 줄바꿈)으로 그리므로 실제 화면과 일치합니다.
