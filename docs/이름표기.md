# 이름·지명을 일본어 읽기로

v2.0부터 인명·지명을 **한자 독음이 아닌 일본어 읽기**로 표기합니다.

```
직전신장  →  오다 노부나가        상삼겸신  →  우에스기 겐신
풍신수길  →  도요토미 히데요시     이달정종  →  다테 마사무네
덕천가강  →  도쿠가와 이에야스     미장(尾張) →  오와리
```

---

## 왜 어려웠나 — 이름 필드는 7바이트

무장 레코드는 스트라이드 44바이트이고, 그 안에서 성·이름이 각 **7바이트 고정**입니다.

```
0x330010: [4] 헤더 | [7] 성 金上 | [7] 이름 盛備 | [7] 능력치 | [3] 여백 | …
                    ↑ 7바이트     ↑ 7바이트      ↑ 바로 뒤에 능력치
```

NUL 을 빼면 6바이트 = **전각 3음절**이 한계입니다.
`노부나가`(4음절 = 8바이트)가 들어가지 않습니다.

레코드를 넓히는 방법도 검토했지만, ×44 계산이 코드 **298곳**에 흩어져 있어
하나라도 놓치면 DB 전체가 어긋납니다. 위험해서 접었습니다.

---

## 어떻게 풀었나 — 반각 1바이트 한글

게임에는 1바이트 문자를 **8px 전진**으로 그리는 반각 경로가 이미 있습니다
(드로잉 루프 `0x08003E6C` 의 else 가지, 폰트 `0x304DF4`, 글리프 12바이트 = 8×12).

실제 게임 텍스트가 **쓰지 않는 ASCII 코드 50칸**을 실측해 찾아내고,
거기에 한글 음절을 넣었습니다.

```
'노' → 0x23,  '부' → 0x24,  '나' → 0x26,  '가' → 0x2A  …
노부나가 = 4바이트  ✓ 7바이트 필드에 여유 있게 들어감
```

- 전각 전진폭도 이미 8px 이므로 반각·전각이 섞여도 자간이 어긋나지 않습니다.
- 갈무리11 Condensed 의 한글 잉크 폭이 7px 이라 8×12 반각 글리프에 그대로 맞습니다.
- 자주 쓰이는 음절 50종을 빈도순으로 배정하고, 나머지는 전각(2바이트)을 씁니다.
  이 배분으로 이름 825종 중 **초과 0종**입니다.

> 배정하는 코드는 '실제 게임 텍스트에 등장하지 않는 것'만 골라야 합니다.
> `tools/halfwidth.py` 의 `FREE_CODES` 가 그 실측 결과이며,
> 번역을 크게 고치면 다시 확인해야 합니다.

## 본문 속 이름도 바꿨다

대사·인물 열전은 이미 한자 독음으로 번역돼 있었으므로
**'독음 → 일본어 읽기'** 로 다시 치환했습니다 (`tools/names.py`).

### 오치환을 막는 장치

한자 독음은 한국어 낱말과 자주 겹칩니다. 실제로 걸러낸 사례들입니다.

| 원인 | 잘못된 결과 | 대응 |
|---|---|---|
| `移動` vs `伊東`(이동) | 이동시킵니다 → **이토**시킵니다 | 단독 치환 제외 |
| `加賀`(가하) | 기습을 가하거나 → **가가**거나 | 뒤 글자 검사 |
| `前田`(전전) | 인질로 전전하였다 → **마에다**하였다 | 뒤 글자 검사 |
| `結城`(결성) | 동맹을 결성되었다 → **유키**되었다 | 뒤 글자 검사 |
| `日向`(일향) | 일향종 문도 → **휴가** 종 문도 | 단독 치환 제외 |
| `綱成`(강성) | 岡城 성주 → **쓰나시게** 성주 | 이름 단독 치환 금지 |

정리하면 이렇습니다.

1. **이름(名)은 단독으로 치환하지 않습니다.** 성과 함께 올 때만 바꿉니다.
   (`信長`·`秀吉` 등 그 인물이 확실한 36개만 예외)
2. **3음절 이하 이름은 뒤에 조사·구두점이 와야** 이름으로 인정합니다.
   `이동시킵니다`의 '이동'은 뒤가 '시'라서 건너뜁니다.
3. **앞이 한글로 이어지면** 낱말의 일부로 보고 건너뜁니다.
4. 한국어 낱말과 완전히 겹치는 것(`本多`=본다, `大和`=대화)은 단독 제외 목록에 둡니다.

### 동음이의 해소

`光秀`(미쓰히데)와 `光寿`(고주)는 독음이 둘 다 '광수'입니다.
게임의 무장 DB에서 **실제로 존재하는 성+이름 조합 492개**를 읽어
`明智光秀`는 미쓰히데, `本願寺光寿`는 고주로 갈랐습니다.

### 조사 보정

이름이 바뀌면 받침이 달라져 조사가 어긋납니다. 자동으로 고칩니다.

```
가강(받침 O)과  →  이에야스(받침 X)와
수길이          →  히데요시가
겸신은          →  겐신은
```

## 창 넘침 정리

일본어 읽기는 독음보다 깁니다(`수길` 2음절 → `히데요시` 4음절).
그래서 인물 열전이 다시 넘쳤습니다.

원문 자체가 창 크기에 맞춰 **문장 도중에 잘려 있으므로**(`…勝家の死後は前田`),
같은 방식으로 원문 줄 수에 맞춰 잘라냅니다. 자동 처리이며 **61건**이 대상이었습니다.
포맷 코드(`%s`·`%d`)가 있는 문자열은 인자 개수가 달라지면 위험하므로 건드리지 않습니다.

결과: 창 넘침 **0건**.

## 알려진 한계

- **무명 가신의 읽기**는 문헌이 갈리는 경우가 있어 일부 오독 가능성이 있습니다.
  대조표를 보시고 알려주시면 고치겠습니다.
- `備後`(빙고)와 `肥後`(히고)처럼 **독음이 같은 지명**은 번역문만으로 구분할 수 없어
  본문에서 원래 표기를 유지합니다. DB 필드는 원문이 한자라서 정확히 바뀝니다.
- 성 없이 이름만 나오는 무명 무장은 독음이 남을 수 있습니다.
